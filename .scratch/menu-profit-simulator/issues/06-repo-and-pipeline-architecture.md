# Repo and pipeline architecture

Type: grilling
Status: resolved
Blocked by: 01, 03

## Question

How do the generator, DuckDB, SQL, notebook and static dashboard fit together, mirroring the Airbnb project's `etl/` -> warehouse -> `sql/` + notebook shape?

Decide: folder layout; tables and which logic lives in SQL vs Python; the single source of truth for simulation math given a static site (precompute scenario grids to JSON vs re-implement the model in browser JS, and how parity is guaranteed); where the dashboard reads data from; how CSVs, the DuckDB file and exported JSON are versioned; how tests run; dependency management.

## Answer

**Single source of truth for the math:** Python (`sim/`) is the reference implementation, used by the notebook, validation and experiment ranking. A small JavaScript port (`dashboard/sim.js`) drives the live sliders. Python exports golden scenarios (inputs plus expected outputs) and a parity test (`node tests/parity.mjs`, Node as a dev-only dependency) checks the JS matches within a tolerance. Rejected: precomputed grids (cannot cover per-item price changes x cost shocks x substitution x bands) and Pyodide (megabytes, slow load).

**SQL vs Python:** SQL (DuckDB, plain ANSI like the Airbnb project) holds the descriptive layer: item unit cost from recipes x latest ingredient costs, contribution margin, trailing-12-week baseline units, popularity share, menu engineering matrix inputs. Python holds the generator, the simulation model, experiment ranking and exports. The five CSVs load as `raw_*` tables with derived views feeding the simulator. `ground_truth.csv` loads into a separate `validation` schema read only by `sim/validation.py`; the simulator never imports it (the leakage test is a validation-strategy ticket matter).

**Dashboard data and hosting:** one self-contained root `index.html` with the exported data inlined, rendered from `dashboard/template.html` by an export step (works opened as a file; data is small). GitHub Pages serves root `index.html` from `main`. No duplicate `dashboard.html`.

**Versioning, tests, dependencies:** committed: synthetic CSVs, `ground_truth.csv`, golden-scenario fixtures, the generated `index.html`, the executed notebook. Ignored: the `.duckdb` file and caches. Tests: pytest in `tests/` plus the Node parity check. Dependencies: `requirements.txt` (pandas, numpy, duckdb, matplotlib, jupyter, nbconvert, pytest), as in the Airbnb project; `uv` optional locally, not required of readers.

**Layout:**
```
index.html                  generated by export (served by GitHub Pages)
dashboard/  template.html, sim.js
data/synthetic/             five CSVs + ground_truth.csv (validation-only)
data/processed/             menu_warehouse.duckdb (generated, ignored)
etl/        generate.py, load.py, warehouse.py, run_pipeline.py, run_queries.py
sql/        schema.sql (raw_* + validation schema), views.sql, analysis_queries.sql
sim/        model.py, scenarios.py, experiments.py, validation.py (only module reading ground truth)
notebooks/  menu_profit_analysis.ipynb (executed, with outputs)
scripts/    export_dashboard.py, make_golden.py
tests/      test_model.py, test_no_leakage.py, fixtures/, parity.mjs
requirements.txt, README.md, GLOSSARY.md
```
`sim/` takes plain data in and returns plain data out (no DuckDB access), so it is unit-testable, portable to JS and importable from the notebook.

**Notebook:** presentation and analysis layer only. It imports `sim/`, queries DuckDB via `warehouse.get_connection()`, defines no formulas, and is committed fully executed. Story: baseline margins and matrix, a beef shock, price scenarios with band ranges and break-even elasticity, the substitution slider, the experiment backlog, validation results.

**Entry points and run order** (plain Python scripts, no Makefile):
```
pip install -r requirements.txt
python etl/run_pipeline.py        # generate (if CSVs missing) -> load -> create views
python etl/run_queries.py         # business SQL -> printed + saved CSVs
python scripts/make_golden.py     # golden scenarios for parity tests
python scripts/export_dashboard.py   # writes root index.html
pytest && node tests/parity.mjs
jupyter notebook notebooks/menu_profit_analysis.ipynb
```

Open seams owned by other tickets: matrix class rules (ticket 02) fill `sql/views.sql` inputs and the Python classification; backlog scoring (ticket 08) fills `sim/experiments.py`; leakage and parity thresholds (ticket 09).
